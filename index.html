Steps of AI Adoption, mapped to the GitHub and Azure Well-Architected frameworks

Five steps ordered by how much judgement has been delegated, after Boris Cherny. For each, the Microsoft and GitHub capabilities that support it, the Well-Architected pillars that dominate, and the residue neither framework covers.

The structural mismatch. Neither framework defines a maturity model, adoption stages or crawl/walk/run levels — GitHub ships a checklist per pillar, Azure ships an assessment review. Both are point-in-time snapshots of a system that already exists. The steps supply the sequence the pillars leave out; the pillars supply the depth the steps do not. A high pillar score does not authorise the next step, and reaching the next step does not excuse a failed pillar.

GitHub pillars

Productivity · Collaboration · Application Security · Governance · Architecture.

learn.github.com/well-architected

Azure pillars

Reliability · Security · Cost Optimization · Operational Excellence · Performance Efficiency, plus a ten-area AI workload guidance set.

Where they divide

Steps 0–2 are governed almost entirely by GitHub Well-Architected. Steps 3–4 cannot be: orchestration stops being a GitHub configuration problem and becomes an Azure workload.
